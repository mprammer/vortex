# Review of `ae6cf17cd`

This was a source-only correctness review of the three files changed by the
commit. The CUDA toolkit and `nvcc` are unavailable in this worktree, so no Rust
or CUDA compilation was attempted. The correctness reference,
`vortex-cuda/kernels/src/onpair_shmem_4tpt_split8read.cu`, was not modified.

## Changes made

- Changed validation mismatch diagnostics to use `KernelVariant::report_name()`.
  The four look-back geometries load one PTX symbol, so reporting `variant.name`
  made failures from `_w4`, `_w2`, and `_w1` indistinguishable even though their
  result rows have distinct keys.
- Replaced stale comments describing the old single-ticket/base-offset protocol.
  The implementation uses a zero-initialized ticket array, selects one counter by
  epoch, and refuses to reuse a slot. There is no per-launch ticket reset and the
  kernel does not subtract a ticket base.
- Corrected the Rust epoch comment. Dispatch stops before the ticket-ring limit,
  so no launched epoch reaches either ticket-slot reuse or the 30-bit descriptor
  tag wrap.
- Made epoch allocation fail closed with `AtomicU32::fetch_update`. Previously,
  rejected launches continued incrementing the counter; enough retries could
  eventually wrap it and admit reused epochs. Exhaustion now leaves the counter
  pinned at the last usable epoch.
- Clarified the `st.global.cs.u8` operand contract: PTX has no 8-bit register
  class, the `"h"` constraint supplies a 16-bit register, and the store writes its
  low eight bits. Also corrected the copied description of how `_stcsedge`
  differs from the shipped split-read kernel.
- Removed a redundant `as usize` from descriptor-capacity calculation. This also
  avoids adding noise on a line under the crate's strict warning policy.

## Reviewed and intentionally left unchanged

### Warp-wide look-back

The ballot-first walk is correct and was left unchanged.

At the top of an iteration, `exclusive` is the sum of aggregates already consumed
for block ids in `[window_end, blk)`. Lane `l` inspects block
`window_end - 1 - l`, so lane 0 is the nearest unconsumed predecessor.

- If `firstP < firstX`, lanes `0..firstP` contain nearer aggregates followed by
  one inclusive prefix and no unpublished descriptor. Their sum completes the
  prefix through `blk - 1`, and the loop stops.
- Otherwise, lanes `0..firstX` are published aggregates. The code consumes
  exactly lanes `0..firstX - 1` and subtracts exactly `firstX` from
  `window_end`; the unpublished descriptor becomes lane 0 on the next iteration.
  Thus the consumed intervals are disjoint and adjacent: no block can be counted
  twice or skipped.
- When `firstX == 0`, `usable == -1`. Every lane's contribution predicate is
  false, the warp reduction adds zero, and `window_end -= 0`. The loop therefore
  polls the same nearest descriptor without changing the accumulated sum.
- If there is neither a hole nor a prefix in the window, all 32 descriptors are
  aggregates and the code consumes and slides by exactly 32.
- Near the head of the grid, lanes whose computed index is negative synthesize a
  zero-valued `LB_P`. If no nearer real descriptor is unpublished, the nearest
  such lane terminates the walk after all real predecessors have been consumed.
  If a real hole exists, it precedes the synthetic prefix and is polled first.
- Every lane in warp 0 reaches both ballots and every shuffle on every loop
  iteration. Off-end lanes skip only the ordinary acquire load. The loop break
  and window movement depend solely on warp-wide ballot results, so they are
  uniform. Other warps are not named in warp 0's mask and wait at the block
  barrier.
- An `LB_X` lane cannot contribute. When a prefix wins, it is nearer than the
  first `LB_X`; otherwise `usable` ends immediately before the first `LB_X`.
  The local value also starts at zero and is populated only for `LB_A` or `LB_P`.

### Epochs and tickets

`LB_TAG` stores `(epoch & 0x3fffffff)` in flag bits 2 through 31, and readers
compare `LB_EPOCH_OF(flag)` with the same masked `epoch_tag`. The CUDA
`LB_TICKET_SLOTS` and Rust `FUSED_TICKET_SLOTS` are both 16,384, a power of two.
The kernel indexes the ring with `epoch & 16,383`; Rust atomically advances only
when the next epoch is less than 16,384, so no launched epoch aliases a prior
slot. Once exhausted, the atomic value no longer advances and cannot wrap back
into the accepted range.

Epochs currently start at one, and allocation rejects a next epoch greater than
or equal to 16,384. Consequently slot zero is unused and 16,383 slots are
launchable. This is a conservative capacity loss, not a correctness defect, and
changing the epoch-zero policy was outside the necessary fix.

### Descriptor capacity and launch coverage

Let `C = ceil(total_tokens / 128)`, the number of warp chunks. For a look-back
geometry with `w` warps per block, the grid contains `ceil(C / w)` blocks. The
four registered values are `w = 16, 4, 2, 1`, so every grid is at most `C`; the
one-warp geometry is the maximum. Rust allocates `C + 64` descriptors.

All four entries use `KernelLayout::FusedPositions`, and every launch goes through
that match arm. It computes the actual configured grid width and bails before
claiming an epoch or launching if the width exceeds `fused_capacity`. The only
early return is for zero tokens, which needs no descriptors. The capacity guard
therefore cannot be bypassed by any registered look-back geometry.

The extra 64 descriptors were left in place as harmless headroom.

### Streaming byte stores

`st.global.cs.u8 [%0], %1;` follows the PTX store ordering
`st.<space>.<cache-op>.<type>`. The pointer uses the 64-bit `"l"` constraint. The
value is explicitly promoted to `unsigned short` for the 16-bit `"h"` constraint;
PTX permits an integer source register wider than `.u8` and stores the low eight
bits. `volatile` and the `"memory"` clobber keep the indirect write from being
deleted or moved by the CUDA front end. See NVIDIA's
[inline PTX constraint rules](https://docs.nvidia.com/cuda/inline-ptx-assembly/index.html#constraints)
and [PTX `st` definition](https://docs.nvidia.com/cuda/parallel-thread-execution/#data-movement-and-conversion-instructions-st).

A direct diff against the shipped split-read kernel found only comments, private
helper/kernel names, the new byte-store helper, and replacement of the existing
head/tail byte assignments with calls to that helper. Token loads, scans, shared
addresses, output addresses, body stores, predicates, and byte values are
otherwise unchanged. The `"h"` constraint was therefore left unchanged.

### Reporting, loading, filters, and automatic selection

There are 59 `KernelVariant` literals and 59 `report_as` initializers. The
16-warp look-back row reports under the PTX symbol; the 4-, 2-, and 1-warp rows
have unique `_w4`, `_w2`, and `_w1` labels. Both constructors of
`GpuKernelResult` use `report_name()`, as does the corrected validation diagnostic.

The remaining uses of `variant.name` are the two calls that load a PTX module and
function. Those must continue using the actual symbol and were left unchanged.
Applicability is selected from `KernelLayout`, not the report label. The new
aliases contain neither `ablate` nor `_bounds`, so they do not evade the existing
best-kernel exclusions. Every name returned by the automatic selector belongs to
a pre-existing variant with `report_as: None`, so selector lookup is unchanged.

### Rust warning policy

The changed Rust paths use the already imported `AtomicU32` and `Ordering` names;
no redundant `std::sync::atomic` qualification was introduced. The other touched
Rust expressions likewise contain no fully qualified form of an imported item.
